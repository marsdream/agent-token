# Agent Token — 给 AI 智能体的 API 访问令牌

[English](README.md) | 简体中文

一个 WordPress 插件：给你的 AI 智能体发一枚单一的、可随时撤销的令牌来访问 WordPress REST API——不用用户名+密码组合，不用 Basic Auth。

[![在 Ko-fi 上支持](https://img.shields.io/badge/Support%20on-Ko--fi-FF5E5B?logo=ko-fi&logoColor=white)](https://ko-fi.com/aitoken)

## 为什么不用应用密码（Application Passwords）？

你的 AI 助手需要在 WordPress 里干活：写草稿、审稿、改页面。要通过 REST API 做这些，它需要凭据。

WordPress 内置的应用密码，是为“真人把一对用户名+密码粘贴进某个 App 一次”设计的。AI 智能体的工作方式完全不同：

- **智能体的凭据保险库只存一件秘密，不是一对。** 大多数智能体平台（包括 Muse 的自定义连接器）只有一个 API key 输入框。应用密码是用户名*加*密码——根本塞不进去，连接直接被拒。
- **应用密码依赖 Basic Auth。** 很多共享/托管主机会剥离或屏蔽 `Authorization` 请求头，凭据完全正确也会莫名其妙地失败，还没个像样的报错。
- **存一对真实账号密码，难以限权、难以撤销。** 凭据绑在真人账号上，撤销要去翻个人资料页。Agent Token 只存哈希，撤销就是点一下。

说明：如果你的工具链能用应用密码（本地脚本、自有服务器代码），它仍然是个不错的内置选项。Agent Token 是为越来越多“用不了应用密码”的智能体平台准备的。

## 工作原理

- 在 **设置 → Agent Token** 里生成令牌。令牌**只显示一次**，数据库里只存它的 SHA-256 哈希。
- 把令牌映射到一个你指定的 WordPress 用户（比如专门给智能体建的编辑账号）。令牌能做的，恰好就是该用户能做的，不多一分。
- 智能体通过 HTTPS 在请求头 `X-Agent-Token` 里发令牌。没有 Basic Auth，没有用户名，没有别的要配。
- 随时一键轮换或撤销，旧令牌立即失效。
- **复制粘贴完成接入：** 生成令牌时插件会给一段现成的接入说明，粘贴给你的智能体，它就连上了。

## 安全设计

- **只存哈希：** 令牌是 48 个字符的随机串（约 285 比特熵），数据库只保存 SHA-256 哈希，库泄露也不会泄露可用令牌。
- **仅限 HTTPS：** 令牌只在 HTTPS 请求上生效。
- **恒定时间比较**（`hash_equals`），校验令牌不泄露时序信息。
- **映射即最小权限：** 令牌以你映射的那个用户行事。映射到低权限的专用账号，影响面就小。插件自身不授予任何额外权限。
- **没配置就什么都不通：** 没有有效令牌时，任何请求都不会被认证。
- **无遥测、无外联。** 插件从不“打电话回家”，也不新增任何公开写入端点——它只负责把标准 REST API 请求认证为映射用户。

## 智能体自发现（manifest）

插件发布了一个公开只读的 manifest，合规的智能体只凭你的站点地址就能弄清怎么连：

```
GET /wp-json/agent-token/v1/manifest
```

它只返回非敏感的连接信息：站点 URL、认证请求头名、插件版本、是否已配置令牌、映射账号的角色/能力概要。绝不返回令牌、哈希或任何用户的邮箱与个人数据。

## 安装

1. 下载本仓库，把文件放进 `/wp-content/plugins/` 下名为 `agent-token` 的文件夹（或在插件上架 WordPress.org 目录后从那里安装）。
2. 启用插件。
3. （推荐）在 **用户 → 添加用户** 里给智能体建一个专用账号，角色给它需要的最小档（通常是编辑）。
4. 打开 **设置 → Agent Token**，选好映射用户，点 **生成令牌**。
5. 立刻复制令牌与接入说明——令牌只显示这一次——粘贴进智能体的凭据保险库 / 连接器设置。

环境要求：WordPress 6.0+、PHP 7.4+。1.0 版面向单站点安装（暂不支持多站点）。

## 常见问题

**智能体不能直接用我的用户名密码登录吗？**
保存的登录信息服务的是“像真人一样点后台”的浏览器——每次会话都要走完整个登录流程（包括两步验证），而且喂不了别的东西。API 连接器、定时任务和其他无头工具根本见不到浏览器；它们能存的只有一件 API 秘密。令牌可以全天候直接认证 REST API 调用，没有登录仪式——而且和密码不同，它压根不能用来登进 wp-admin。点网页用保存的登录，无人值守的 API 活儿用令牌。

**它支持哪些智能体？**
任何能带自定义请求头调用 REST API 的智能体或工具：Muse 自定义连接器、MCP 类工具、本地自动化脚本等。

**停用或卸载插件会怎样？**
所有令牌立即失效。卸载会把插件设置从数据库中清除。

## 背景

写 Agent Token，是因为一个 AI 助手要在真实站点上审稿，却完全用不了应用密码。它从那时起就一直在生产环境里跑这套工作流。为真实的智能体工作流而建，不是演示样品。
